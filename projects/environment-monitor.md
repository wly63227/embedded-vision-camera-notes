# 综合项目｜环境监测终端

## 1. 项目目标

制作一个可长期运行的温湿度监测终端：周期采集传感器，在 OLED 上显示，通过串口命令配置；可选 ESP32/MQTT 上报。重点是可靠性、可测试性和可复现性。

## 2. 最小硬件

- STM32 Nucleo 或 ESP32 开发板。
- BME280 / AHT20 等数字温湿度传感器。
- 0.96 寸 I²C OLED（常见控制器 SSD1306）。
- 一个按键和一个 LED；面包板与跳线。

连接前核对模块原理图和电压。若传感器与 OLED 地址冲突或总线电容过大，拆分总线或调整器件配置。

## 3. 功能需求

### 必做

- 上电自检：显示固件版本、传感器 ID 和启动结果。
- 默认每 1 秒采样一次；显示当前值、趋势和错误状态。
- 串口命令：`status`、`period <ms>`、`led on|off`、`reset-stats`。
- 保存最小/最大/均值；处理计数溢出和无有效样本。
- 连续 3 次采样失败进入降级状态，之后按退避策略恢复。
- 主循环无长时间阻塞；所有外设等待都有超时。

### 选做

- FreeRTOS 多任务实现。
- MQTT 上报、离线状态和断线重连。
- 参数保存到 Flash，带版本和 CRC。
- 看门狗、复位原因记录、故障现场保存。

## 4. 非功能需求

- 连续运行 24 小时，无死锁、异常复位和持续内存增长。
- 传感器拔出后 2 秒内显示错误，系统保持串口可用。
- 串口输入随机字节和超长行不会越界或阻塞。
- 所有单位明确；用户输入有范围限制。

## 5. 建议架构

```text
button ──> app state machine ──> display service ──> OLED driver
                     ^
sensor driver ──> sample service ──> statistics
                     |
                     +──> telemetry (optional)
UART ISR ──> ring buffer ──> command parser ──> app events
```

硬件访问通过 `bsp/` 适配；业务层使用逻辑值和结构化错误，不直接调用 HAL。

## 6. 里程碑

1. 点灯、串口、I²C 扫描分别通过。
2. 读取传感器 ID 和单次原始数据。
3. OLED 显示固定文本，再显示真实样本。
4. 加入非阻塞调度和状态机。
5. 加入命令行、统计和错误恢复。
6. 加入测试、文档和 24 小时稳定性运行。
7. 可选：迁移 FreeRTOS 或增加 MQTT。

每个里程碑单独提交，保持可运行。

## 7. 测试矩阵

| 场景 | 预期行为 | 证据 |
|---|---|---|
| 正常启动 | 自检通过，1 Hz 更新 | 启动日志 + 视频 |
| 传感器未连接 | 超时返回，进入降级，串口可用 | 错误日志 |
| 传感器恢复 | 有限重试后恢复采样 | 状态迁移日志 |
| OLED 失败 | 采样和串口继续，报告显示故障 | 日志 |
| 超长串口命令 | 拒绝并清空当前行，不越界 | 自动测试 |
| `period 0` | 报参数范围错误 | 命令响应 |
| tick 回绕 | 周期调度仍正确 | 主机端测试 |
| 运行 24 小时 | 无异常复位/卡死 | 心跳和统计日志 |

## 8. 交付物

- 源码、构建说明、引脚表、模块图。
- 测试报告和至少一段演示视频。
- 关键波形：I²C 事务、周期信号或 UART 数据。
- 一页复盘：最难问题、根因、取舍和下一版计划。
