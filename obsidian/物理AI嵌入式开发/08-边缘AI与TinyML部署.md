# 边缘 AI 与 TinyML 部署

## 先问：模型该放在哪里

| 位置 | 适合任务 | 约束 |
|---|---|---|
| MCU | 关键词、异常检测、简单时序分类 | RAM/Flash 小、算力有限、确定性较好 |
| Linux 边缘板 | 视觉、语音、多模态、局部规划 | 功耗高、调度与启动复杂 |
| 云端 | 大模型、集中分析、训练 | 网络延迟、隐私、断网不可用 |

## TinyML 完整流程

```text
定义任务 → 采集真实数据 → 清洗与标注 → 划分数据集 → 建立传统基线
→ 训练模型 → 量化/剪枝 → 目标板部署 → 测延迟/内存/功耗 → 现场回归
```

## 数据比模型更先

- 训练/验证/测试按场景、设备或人员合理隔离，避免泄漏。
- 保存原始传感器数据、固件版本、采样配置和标注依据。
- 覆盖正常、边界、故障、背景变化和未知类别。
- 先用阈值、滤波或小型传统模型建立基线。

## 部署预算

为每个模型记录：

- 模型 Flash 占用、arena/scratch RAM、峰值栈。
- 平均与最大推理延迟、输入窗口时长。
- 准确率之外的混淆矩阵、召回率和拒识率。
- 推理期间功耗与温度。

Arm Cortex-M 可使用 CMSIS-NN 优化量化神经网络算子；也可评估 TensorFlow Lite Micro、厂商工具或 Edge Impulse。工具选择服从目标芯片和可复现性。

## 安全包络

模型输出先经过：

1. 置信度/有效性检查。
2. 物理范围与变化率限制。
3. 状态机和安全规则。
4. 传统控制器/轨迹生成器。

模型不确定时应拒绝、减速、保持或停车，而不是“尽力猜”。

## 入门项目

- IMU 手势分类：MCU 采集并推理，LED 显示类别。
- 电机异常检测：电流/振动窗口分类，故障只报警不直接切断关键设备。
- 视觉云台：边缘板检测目标，MCU 负责舵机闭环和限位。
