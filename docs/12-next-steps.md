# 12｜综合项目、作品集与进阶方向

## 完成项目，而不是永远看教程

使用 [环境监测终端项目书](../projects/environment-monitor.md) 完成一个端到端作品。把需求、接口、架构、测试和已知限制一起提交。面试或课程展示时，工程判断比“用了多少模块”更重要。

## 作品集最低要求

- 项目目标、硬件清单、接线图/引脚表。
- 一键可复现的构建步骤和工具版本。
- 模块图、状态机或任务图。
- 关键技术选择及替代方案。
- 测试表：正常、边界、故障恢复和长时间运行。
- 演示图片/视频与串口日志。
- 已知问题和下一步，而不是隐藏缺陷。

## 进阶方向

### 嵌入式 Linux

补充操作系统、进程线程、虚拟内存、设备树、交叉编译、Bootloader、内核与驱动模型。建议先熟练 MCU 和 C，再进入驱动开发。

### 控制与机器人

学习离散系统、传感器融合、PID、实时调度、电机驱动和安全停机。先在仿真/低功率平台验证，再连接实际执行器。

### 低功耗

建立能量预算，理解运行/睡眠状态、唤醒源、外设时钟门控和测量方法。不要只读数据手册典型值，要在真实板上测量。

### 固件安全

学习威胁建模、安全启动、固件签名、密钥保护、调试口策略、回滚保护和安全更新。安全不是最后附加的功能。

### 工程化

继续学习交叉编译构建、静态分析、单元/集成/HIL 测试、CI、版本化协议、发布产物和崩溃诊断。

## 自测清单

- 能否只凭手册让一个陌生 I²C 传感器工作？
- 能否解释并测量一个周期任务的抖动？
- 能否从 HardFault 地址定位到源码？
- 能否设计不会被半包、粘包和恶意长度击穿的协议解析器？
- 能否证明系统在传感器掉线、串口洪泛和网络断开后仍有确定行为？

全部能做到，就已经跨过“会点灯”到“能做可靠系统”的门槛。
