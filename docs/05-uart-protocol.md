# 05｜UART、缓冲区与帧协议

## UART 基础

双方需约定波特率、数据位、校验位和停止位。UART 没有时钟线，波特率误差过大、地线未共地或电平标准不匹配都会导致乱码。TTL UART、RS-232、RS-485 的电气层不同，不能直接混接。

## 从阻塞到异步

学习顺序：

1. 阻塞发送与接收，验证连线和配置。
2. 中断接收单字节，理解事件流。
3. 环形缓冲区解耦 ISR 与解析器。
4. DMA + 空闲线检测处理不定长数据。

ISR 只把字节写入缓冲区；主循环或任务负责解析。缓冲区满时必须有明确策略：丢新数据、覆盖旧数据、流控或报告错误。

## 文本命令协议

第一版可用行协议：

```text
led on\r\n
period 1000\r\n
status\r\n
```

限制最大行长，处理退格、空行、未知命令、数字溢出和超时。不要对未终止的接收缓冲区直接调用字符串函数。

## 二进制帧

示例格式：

```text
SOF(2) | VERSION(1) | TYPE(1) | LENGTH(2) | PAYLOAD(N) | CRC16(2)
```

解析器必须逐字节工作，并能在噪声、半包、粘包、错误长度和错误 CRC 后重新同步。`LENGTH` 在使用前与最大负载比较。

## 实验：可测试命令行

实现 `led on/off`、`period <ms>`、`status` 三条命令。解析核心不直接依赖 UART HAL：输入一串字节，输出命令对象或错误码。这样可在电脑上做自动测试。

测试至少覆盖：

- 一次输入完整命令、逐字节输入、两条命令粘连。
- 超长行、非法参数、参数边界、空白字符。
- 环形缓冲区回绕与溢出。

## 验收标准

- 连续发送 1000 条命令，无死锁和越界。
- 接收速度短时高于处理速度时，系统按设计报告或处理溢出。
- 能解释为什么在中断里调用 `printf` 容易出问题。
