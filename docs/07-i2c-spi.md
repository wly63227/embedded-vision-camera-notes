# 07｜I²C、SPI 与传感器驱动

## I²C

I²C 使用开漏 SDA/SCL 和上拉电阻。一次事务包含起始、地址、读写位、ACK/NACK、数据和停止。常见错误：

- 7 位地址与左移后的地址混淆。
- 没有上拉、上拉过弱或总线电容过大。
- 电源和逻辑电平不兼容。
- 器件上电后尚未就绪。
- 从机拉低 SCL/SDA 导致总线卡死。

## SPI

SPI 通常包含 SCLK、MOSI、MISO 和每个从机的 CS。双方必须匹配 CPOL、CPHA、位序和最大时钟频率。CS 的前后时序可能决定命令是否生效。

## 驱动分层

```text
应用层：显示温湿度、报警策略
器件层：bme280_read_sample()
总线适配：bus_read_registers(address, reg, buffer, length)
平台层：HAL_I2C / ESP-IDF I2C API
```

器件驱动返回结构化错误码，并设置超时。应用层不应知道寄存器细节；器件层也不应直接决定 UI。

## 读数据手册的方法

1. 查绝对最大额定值和推荐工作条件。
2. 查引脚、地址选择和上电时序。
3. 读取固定的 `WHO_AM_I` / `CHIP_ID` 寄存器。
4. 配置最小工作模式。
5. 读取原始数据，对照复位值和转换公式。
6. 最后再启用高级模式、中断和低功耗。

## 实验：传感器 + OLED

- 启动时扫描已知地址范围仅用于诊断；正式驱动使用配置地址。
- 读取芯片 ID，不匹配时停止并报告。
- 每秒读取一次数据，OLED 刷新不超过 10 Hz。
- 连续失败 3 次进入错误状态，周期性尝试恢复。
- 用逻辑分析仪确认地址、ACK 和时钟频率。

## 验收标准

- 拔掉传感器后系统不死锁，并显示明确错误。
- 重新连接后按设计恢复，或提示需要重启。
- 驱动代码不依赖具体 UI，能用假总线做主机端测试。
