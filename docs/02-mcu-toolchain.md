# 02｜MCU、内存与工具链

## MCU 的基本组成

微控制器把 CPU、Flash、SRAM、时钟、复位、GPIO、定时器、通信外设和调试模块集成在一颗芯片中。程序通常从复位向量开始：启动代码设置栈、复制 `.data`、清零 `.bss`，再进入 `main()`。

典型内存区域：

- `.text` / `.rodata`：代码与只读常量，通常在 Flash。
- `.data`：有初值的可写全局/静态变量，运行时在 RAM。
- `.bss`：零初始化的全局/静态变量，在 RAM。
- heap：动态分配区；资源受限系统应严格控制。
- stack：局部变量、返回地址和调用现场；递归和大数组会迅速消耗栈。

## 读文档的顺序

1. 开发板用户手册/原理图：LED、按键、晶振、调试器连到哪些引脚。
2. 芯片数据手册：封装、引脚、电气限制、外设列表。
3. 参考手册：寄存器和外设行为。
4. 编程手册/内核文档：Cortex-M 异常、NVIC、SysTick 等。
5. Errata：已知硬件问题和规避方法。

## HAL、LL 与寄存器

- HAL 适合快速完成业务和验证外设组合。
- LL/寄存器适合理解硬件、减少开销或实现特殊时序。
- 入门时可用 HAL 建立结果，再对一个简单外设做寄存器版，对照理解时钟、模式、数据寄存器和状态位。

不要在同一外设上无计划地混用多层抽象；代码生成器重新生成前，确认自定义代码位于保留区或独立文件。

## 调试器基础

练习以下操作：

- 断点、条件断点、单步进入/跳过/跳出。
- 查看局部变量、内存、调用栈和外设寄存器。
- 查看反汇编，理解一条 C 语句可能对应多条指令。
- 用 watchpoint 发现“谁修改了这个变量”。

## 实验：从复位到 main

1. 新建最小工程，在 `main()` 第一行打断点。
2. 打开启动文件，找到向量表、复位处理函数和栈顶定义。
3. 对照链接脚本记录 Flash/RAM 地址与长度。
4. 增加一个已初始化全局变量、一个未初始化全局变量和一个局部变量，观察它们的位置。
5. 查看构建报告或 `.map` 文件，记录代码、数据和 BSS 大小。

## 验收标准

- 能画出从复位到 `main()` 的执行流程。
- 能说明栈溢出可能表现为 HardFault、数据损坏或随机复位。
- 能根据芯片型号找到正确的数据手册、参考手册和勘误表。
