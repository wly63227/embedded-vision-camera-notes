# 08｜软件架构、状态机与可靠性

## 分层与依赖方向

建议结构：

```text
app/       业务状态机、策略
services/  采样、存储、通信服务
drivers/   具体器件驱动
bsp/       板级引脚和外设适配
platform/  HAL、RTOS、时间、日志接口
```

上层依赖抽象接口，不直接散落 HAL 调用。硬件差异收敛在 BSP 和平台适配层。

## 协作式主循环

小系统不一定需要 RTOS：

```c
for (;;) {
    uint32_t now = platform_millis();
    button_task(now);
    sensor_task(now);
    display_task(now);
    protocol_task(now);
    watchdog_task(now);
}
```

每个任务短时间返回，使用时间戳决定是否工作。时间比较应支持计数器回绕，例如 `(int32_t)(now - deadline) >= 0`，并保证时间间隔不超过表达范围。

## 状态机

把隐含流程变为显式状态和事件。每个状态定义：进入动作、允许事件、退出条件、超时和错误路径。参考 `examples/portable/state_machine.c`。

## 错误处理

- 区分可恢复错误、配置错误和致命错误。
- 错误码保留上下文；日志记录模块、事件、时间和关键参数。
- 超时必须有上限；失败重试应限次并考虑退避。
- 看门狗只在系统关键任务都健康时喂，不要在无条件定时器中喂狗。

## 动态内存

资源受限或强实时系统中优先静态分配。若使用堆：固定所有权规则、检查失败、测量碎片风险，并避免在 ISR 中分配。FreeRTOS 的不同 heap 实现具有不同能力，不应只凭名字选择。

## 代码质量检查表

- 所有数组访问都有边界依据。
- 所有等待硬件状态的循环都有超时。
- ISR 与主流程共享数据有同步设计。
- 错误不会被静默吞掉。
- 单位体现在变量名或类型中，如 `timeout_ms`。
- 协议输入在使用前校验长度、范围、版本和校验值。

## 实验：非阻塞设备状态机

实现 `BOOT → SELF_TEST → RUN → DEGRADED → ERROR`。模拟传感器间歇失败和永久失败，验证重试、降级和恢复。记录每次状态迁移原因。
