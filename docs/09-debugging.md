# 09｜系统化调试手册

## 调试不是随机改代码

使用固定循环：

1. **描述**：最小、可观察、可重复的故障是什么？
2. **界定**：最后一个正确点和第一个错误点在哪里？
3. **假设**：列出最可能的 3 个原因，并写出区分它们的实验。
4. **测量**：一次只改变一个变量，保存日志、寄存器或波形。
5. **修复**：解释根因，而不是只让症状消失。
6. **回归**：增加测试或断言，防止再次发生。

## 分层检查清单

### 完全不运行

- 电源电压、复位脚、BOOT 配置、芯片方向。
- 调试器连接和芯片型号。
- 是否进入 HardFault、默认中断或看门狗复位。
- 时钟配置是否超过芯片/电压允许范围。

### 串口乱码

- 波特率、数据格式、时钟源、共地、电平标准。
- 实际波特率是否被错误主频影响。
- 字符串是否越界、是否含二进制数据。

### I²C 无 ACK

- 供电、上拉、7 位地址、引脚复用、时钟频率。
- 逻辑分析仪上是否有起始、地址和第九个时钟。
- 器件是否需要上电等待或退出复位。

### 随机崩溃

- 栈溢出、数组越界、空指针、竞态、未初始化数据。
- ISR 优先级和 RTOS API 调用规则。
- 电源跌落、EMI、看门狗或错误的低功耗恢复。

## HardFault 现场

不要只在死循环里停住。至少保存：堆栈帧中的 PC/LR、故障状态寄存器、复位原因和固件版本。用 ELF 和 map 文件把 PC 地址映射到函数与行号。

## 故障报告模板

```text
标题：一句话描述现象
环境：开发板、芯片、固件提交、工具版本
复现：从上电开始的最短步骤
预期：应该看到什么
实际：看到了什么
证据：日志、寄存器、波形、最小代码
排除：已验证不是哪些原因
根因：机制解释
修复：修改内容和风险
回归：新增的测试
```

## 故障注入练习

主动制造并定位：UART 波特率错误、I²C 地址错误、数组越界、定时器时钟计算错误、任务栈过小。每次都保留故障前后的证据。
