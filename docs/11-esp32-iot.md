# 11｜ESP32 与物联网分支

本章是选修分支。先完成 MCU、通信和并发基础，再引入网络复杂性。

## ESP-IDF 工作流

使用稳定版 ESP-IDF，从官方 `hello_world`、`blink`、Wi-Fi station 示例开始。基本流程是配置、构建、烧录、监视。项目路径避免特殊字符和过深目录，以减少工具链问题。

## Wi-Fi 状态机

网络不是“调用连接函数就结束”。至少包含：未配置、连接中、已连接、获取 IP、在线、退避重连和配置错误。区分 Wi-Fi 连接、IP 可用、DNS 可用和应用服务器可用。

## MQTT 最小知识

- Topic 是层级字符串；payload 格式需版本化。
- QoS 描述交付语义，不等于端到端业务幂等。
- 保活、遗嘱、保留消息和会话设置会改变行为。
- 断线重连采用有上限的指数退避并加入抖动，避免设备群同时冲击服务。

示例消息：

```json
{
  "schema": 1,
  "device_id": "lab-node-01",
  "sequence": 42,
  "temperature_milli_c": 23875,
  "humidity_milli_percent": 51720
}
```

## 安全底线

- 不把真实 Wi-Fi 密码、令牌或私钥提交到 Git。
- 生产系统使用 TLS，并设计证书/密钥的配置与更新机制。
- 对 OTA 固件验证签名、版本和回滚条件。
- 所有云端输入都视为不可信：校验长度、类型、范围和权限。

## 实验：可恢复的数据上报器

每 10 秒上报一个模拟样本。断开路由器 2 分钟后恢复，设备应自动重连；本地采集不应因网络断开而停止。记录离线期间数据丢弃或缓存策略。
