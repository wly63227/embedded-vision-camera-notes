# 00｜学习路线与开工准备

## 目标

建立可持续的学习节奏，准备开发环境，并完成“编辑—编译—烧录—观察—调试”的第一个闭环。

## 12 周计划

| 周 | 学习内容 | 必做实验 | 验收证据 |
|---|---|---|---|
| 1 | C 语言、Git、编译过程 | 位操作练习；电脑运行单元测试 | 测试全通过；能解释指针和数组差异 |
| 2 | MCU、存储器、工具链 | 点灯、串口输出、断点 | LED 现象；串口日志；变量监视截图 |
| 3 | GPIO、EXTI、中断、消抖 | 按键切换 LED 模式 | 连续按 30 次无误触发 |
| 4 | 时钟、定时器、PWM | 呼吸灯或蜂鸣器 | 实测频率和占空比 |
| 5 | UART、帧协议、环形缓冲区 | 串口命令行 | 粘包/半包测试通过 |
| 6 | ADC、采样、DMA、滤波 | 电位器/内部温度采样 | 原始值、换算值和误差记录 |
| 7 | I²C、SPI、数据手册 | 读取传感器 ID，OLED 显示 | 总线波形或日志 |
| 8 | 模块化、状态机、错误处理 | 非阻塞菜单/设备状态机 | 主循环无长延时 |
| 9 | 系统调试与可靠性 | 制造并定位 3 类故障 | 故障报告包含证据链 |
| 10 | FreeRTOS 基础 | 采集、显示、通信三任务 | 队列传递数据，无共享竞态 |
| 11 | ESP32/Wi-Fi/MQTT（可选） | 上报模拟数据 | 断网后能恢复或给出错误状态 |
| 12 | 综合项目与作品集 | 环境监测终端 | README、演示视频、测试记录 |

## 工具准备

### STM32 路线

- STM32CubeIDE / STM32CubeMX、板载 ST-LINK 驱动。
- 串口终端：IDE 内置终端、PuTTY、MobaXterm 或其他熟悉工具。
- 先从开发板官方示例开始，确认 USB 线支持数据传输。

### ESP32 路线

- ESP-IDF 稳定版及其工具链，或 VS Code 的 ESP-IDF 扩展。
- 使用 `hello_world` 和 `blink` 官方示例验证编译、烧录与监视。

### 通用工具

- Git；支持 C 的编辑器；万用表。
- 逻辑分析仪不是入门必需品，但排查 I²C、SPI、UART 时非常有价值。

## 第一个闭环

1. 新建厂商推荐的空工程或板级工程。
2. 编译原始工程，确认零错误。
3. 配置一个 LED GPIO，烧录后周期翻转。
4. 配置 UART，每秒输出递增计数。
5. 在计数变量更新处打断点，单步观察变量和 GPIO 寄存器。
6. 提交到 Git，提交信息写清“实现了什么、如何验证”。

## 验收问题

- 编译、链接和烧录分别做什么？
- Debug 与 Release 构建有什么差别？
- CPU 停在断点时，定时器和外设是否一定停止？为什么要查调试配置？
- `.elf`、`.hex`、`.bin` 和 `.map` 文件各有什么用途？

## 卡住时的顺序

供电 → USB/驱动 → 芯片型号 → 下载接口 → 时钟 → 引脚复用 → 外设配置 → 应用逻辑。每一步都记录“预期、实际、证据”，不要一次改多个变量。
