# 06｜UART 与控制协议：让坏数据不能成为动作

**前置：** 02、04、05。**硬件：** 开发板 USB 虚拟串口。**产出：** 能解释一条完整控制帧，并测试断线停机。

## UART 与 USB 虚拟串口

UART 按约定波特率发送字节；本课程使用 115200、8 数据位、无校验、1 停止位（8N1）。NUCLEO 的 ST-LINK 把 USART2（PA2/PA3，按板级焊桥确认）桥接成电脑串口。因此当前路线不需要额外 USB-TTL 模块。Windows 在设备管理器查看实际 COM 号。

收到一个字节不等于收到一条命令。USB 与串口可能拆包，程序需要持续收字节，到换行才解析整行。缓冲区满、格式错误、校验失败、序号重复都不能刷新运动超时。

## 本课程协议

```text
P,序号,水平脉宽us,俯仰脉宽us,两位大写十六进制XOR\n
STOP\n
ARM\n
```

`P` 帧的 XOR 只覆盖最后一个逗号之前的 ASCII 字节，例如覆盖 `P,0,1500,1500`，不覆盖校验字段前的逗号和换行。使用配套编码函数生成，不靠手写猜校验值。序号 0～65535 按模递增，允许正常回绕；同一会话只接受向前且跨度小于半圈的序号。

开机默认解除锁存但 PWM 关闭。STOP、超时或串口行错误触发停机锁存；必须发送 ARM 才能接收新的 P 帧。ARM 本身不启动 PWM，也不刷新看门时间。电脑启动先发 STOP、再 ARM，重新建立序号会话。ARM 是人为重新开始的指令，不能自动定时重发。

这是一条短距离、教学用串口协议。XOR 能检出部分传输错误，不是密码学认证，也不保证检出所有双字节错误。需要更强可靠性时升级 CRC、确认应答与重放策略。

## 时间与运动都要有边界

MCU 限制每次更新的脉宽变化速度，合法命令范围为 1200～1800 μs。超过 300 ms 未收到新的合法 P，取消 PWM 并锁存。画面看不到目标时，电脑不持续发送旧位置，而是停止发送 P，让 MCU 超时；用户重新运行程序后才 ARM。

当前样例不提供 MCU 应答，所以电脑打印 SENT 只表示写入串口，不代表执行成功。实机验收必须结合波形、现象与固件状态；扩展题再加入 ACK。

## 实操 L06

1. 用 Python 编码函数生成帧，通过串口工具发送（追加换行）。
2. 改坏校验位、重复序号、输入 99999、发送超长行。
3. 连续发送有效帧，然后拔掉 USB 数据线，保持舵机电源；观察 300 ms 左右停脉冲。
4. 重接后确认 P 不能解除锁存，ARM 后的新 P 才能开始。

**通过条件：** 错误数据不会产生新动作；重复包不延长超时；能说明“停脉冲可能卸力”的物理后果。
