# 03｜开发板、编译与调试

**前置：** 01、02。**硬件：** NUCLEO-F401RE、匹配的 USB 数据线；无需另购 ST-LINK。**产出：** 可重复烧录的最小工程。

## 三种计算设备

电脑运行操作系统，适合图像与文件。MCU 把处理器、内存、定时器和 GPIO 集成在一个芯片里，适合按确定周期做控制。树莓派是能运行 Linux 的小电脑，承担后续独立图像计算；它不能直接替代所有 MCU 的实时职责。

编译器把 C 编译成目标代码，链接器把程序与库按芯片内存布局组合成固件。烧录将固件写进 Flash。调试器可以暂停 CPU、看变量与调用栈。NUCLEO 的板载 ST-LINK 和虚拟串口通过同一根 USB 连接电脑；这些是不同功能。

## 建立第一个工程

从 ST 官方安装 STM32CubeIDE。使用 Board Selector 选择 **NUCLEO-F401RE**，创建 C 工程；保留板级默认配置。允许工具获取对应 STM32CubeF4 包，记录 IDE 和包版本。不同版本菜单位置会变，目标始终是板型正确、能生成代码、能调试。

先不要连接舵机。编译一次，解决所有报错。连接板载调试口的数据线，进入 Debug，在 `main` 处暂停。单步走到主循环，再运行。若 USB 只供电不传数据，电源灯亮但调试器和串口都可能找不到。

## 为什么代码放 USER CODE 区

CubeMX 负责生成初始化代码，重新生成时会覆盖很多区域。自编应用放进独立 `.c/.h` 文件，通过 USER CODE 区调用。保留 `.ioc` 配置，别人才能复现时钟与引脚。把“我电脑上的一个工程能运行”升级为“仓库里包含配置、版本和接线说明”。

本库提供可移植的云台应用模块和 [精确接入步骤](../../firmware/stm32_gimbal/README.md)，并未附带整套 ST HAL、编译器或已验证的 `.ioc`。需要你按板型生成工程；不要把应用源码当成可直接烧录的完整镜像。

## 实操 L03

1. 创建工程并确认调试器能停在 `main`。
2. 在 Watch 窗口观察自己的限幅函数结果。
3. 删除一个分号，体验编译器的文件名与行号提示，然后修复。
4. 保存 IDE 版本、板子丝印、`.ioc` 和一次调试截图。

**通过条件：** 不依赖上次残留镜像，重新构建后能调试；能说明编译失败、烧录失败和运行错误是三个阶段。
