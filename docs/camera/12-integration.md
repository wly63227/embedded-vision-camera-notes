# 12｜系统联调、状态机与毕业演示

**前置：** 01～11。**硬件：** V1 全套。**产出：** 有日志、有失败测试、有边界说明的项目。

## 分层验收

调试顺序：电源 → 固件时基 → 单轴脉宽 → 双轴限位 → 串口 → 静态视觉 → 无负载控制方向 → 轻载闭环。每加一层都保留上一层可独立运行的版本。相机画面变暗、舵机突然重启和串口断开可能是共同的供电或线缆问题，不必首先怀疑算法。

## 状态的含义

电脑端 TRACK 表示本帧有目标；LOST 表示暂时缺失且不发送位置命令；超过 300 ms 进入 STOP，锁存后必须退出并由用户重启。MCU 上电 PWM 关闭，ARM 后等待合法位置，活动期间独立计时，STOP/超时会停脉冲并锁存。电脑冻结不能取消 MCU 自己的超时保护。

软件 STOP 是停止控制脉冲，某些舵机将卸力。它不等于物理断电或机械刹车。桌面轻载、固定支架和电源开关是本实验的一部分；不允许直接承载单反、无反、手机等重物。

## 接入命令

无串口先验证画面和 sign，再运行，例如：

```powershell
.\.venv\Scripts\python.exe examples/camera_tracker/live.py --camera 0 --port COM5 --pan-sign 1 --tilt-sign -1
```

COM5 和方向只是命令格式示例，必须换成自己的实测值。程序启动发送 STOP、ARM；q、空格、异常退出尝试发送 STOP。USB 硬断线时 STOP 可能无法送达，由 MCU 超时兜底。终端显示并不能替代逻辑分析仪实测。

## 日志怎样帮助定位故障

记录时间、帧号、主体坐标、构图点、误差、脉宽、模式和是否发送。保留一份参数文件或启动命令、固件提交、硬件版本与一段对照视频。项目验收表见 [毕业项目](project.md)。日志不要默认包含个人面部原图。

## 实操 L12

1. 静止目标置于左、中、右三个位置，各录 10 秒，比较稳态误差。
2. 遮挡目标 1 秒、拔掉相机、结束上位机、拔掉数据线，分别测试停机。
3. 发送损坏帧、重复帧、超范围命令、无换行超长数据。
4. 同时运动两轴并监测 MCU 是否重启；出现异常先脱载查电源。
5. 故障后确认不会自行恢复运动，由人工检查后重启。
