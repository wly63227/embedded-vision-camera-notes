# 11｜模式识别：从规则到可评估的模型

**前置：** 08～10。**硬件：** 电脑和摄像头即可。**产出：** 人脸检测基线与自己整理的评估表。

## 分类、检测与跟踪

分类回答“图里是什么”，检测回答“是什么、在哪里”，跟踪回答“下一帧还是不是同一个目标”。相机自动构图至少需要位置；如果多人时总切换到最大的人脸，就还没有建立稳定的主体身份。

模式识别的一条基本流程是：采集带标签的样本 → 提取特征或学习特征 → 训练/设定决策器 → 对未参与训练的数据评价。绿色阈值也是一种规则分类，但不能因此宣称能识别任意物体。

## 先运行可解释的检测基线

```powershell
.\.venv\Scripts\python.exe examples/camera_tracker/live.py --detector face
```

基础程序使用 OpenCV 自带的 Haar 正脸级联模型，免下载额外权重。它会漏掉侧脸、遮挡、小脸，也会误检纹理。它只定位人脸，不识别具体身份；没有深度模型的类别置信度。保持默认无串口，先建立视觉表现。

## 数据怎样分才不自欺

建立 3 个不同拍摄时段的数据集，每个至少 30 张。训练/调参、验证、最终测试按时段或场景划分，而不是把相邻视频帧随机打散；相邻帧太相似会造成泄漏。记录是否有目标、目标框和光照条件。照片只使用自己有权处理的素材，不把个人原图默认提交公共 GitHub。

真正的模型训练先使用配套的颜色直方图最近类中心：每张图提取 HSV 直方图，按类别求平均特征，预测距离最近的类别。它是可训练的图像分类基线，不定位物体、不识别形状，而且一定会选择某个已知类别，暂时没有未知类别拒识。

把自己拍的图片按 `datasets/train/green/`、`datasets/train/red/`、`datasets/test/green/`、`datasets/test/red/` 分好目录，训练与测试使用不同拍摄时段。每类至少各拍 20 张训练图、10 张测试图。执行：

```powershell
.\.venv\Scripts\python.exe examples/camera_tracker/histogram_classifier.py self-test
.\.venv\Scripts\python.exe examples/camera_tracker/histogram_classifier.py train --data datasets/train
.\.venv\Scripts\python.exe examples/camera_tracker/histogram_classifier.py test --data datasets/test
```

测试输出混淆矩阵（行是真实类别，列是预测类别）。只凭这两种颜色分得好，不能推断能区分同色的杯子和球。再学线性分类、交叉熵、梯度下降，最后接入预训练轻量目标检测器；自选权重要另行核查来源、许可证与输入预处理。

## 不只看准确率

按匹配标准（例如 IoU≥0.5）统计 TP/FP/FN，一对一匹配，不能让一个预测匹配多个真值。精确率 `TP/(TP+FP)`，召回率 `TP/(TP+FN)`；分母为 0 时记录未定义。再量处理耗时中位数/P95、目标切换次数和丢失率。高帧率但经常追错人并不合格。

## 实操 L11

1. 在三个场景用相同设置录制绿色检测与正脸检测结果。
2. 标注至少 90 张测试图片，按条件统计漏检与误检。
3. 扩展实现“上一帧框 IoU 最大的候选优先”，比较多人时的切换次数。
4. 低可信度、目标过小和检测丢失都走停止策略，再接入云台。

**通过条件：** 能用数字说明某种方法在哪些场景失效；区分已提供的 Haar 基线与尚需自己训练/接入的模型。课程提供进阶实验任务，不声称附带训练完成的专用检测模型。
