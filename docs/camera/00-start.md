# 00｜第一次运行：先让电脑模拟一个闭环

**前置：** 无。**硬件：** 现有电脑。**产出：** 一份模拟日志和一次亲手修改。

## 从熟悉的现象开始

视频会议里的人脸框只是“发现了人”。若程序还让相机转动，把脸放在画面三分点，它还做了“决策”和“执行”。本项目把这三件事拆开学，避免一开始就把神经网络、接线和电机故障混在一起。

程序是写给计算机的一组明确步骤。源码是你能读的文字；解释器执行 Python，编译器将 C 变成机器程序。文件夹只是组织资料，终端用于输入命令。下方命令中的 `python` 是程序名，其余内容是参数；不要把 `PS C:\...>` 提示符复制进去。

## 先准备工具

安装 Python 3.12 或更高版本、代码编辑器、Git；都从 [官方来源](sources.md) 下载。Windows 安装 Python 时选择将其加入 PATH，重开终端。执行：

```powershell
python --version
git --version
```

若 `python` 打开商店而不是输出版本，可尝试 `py -3.12 --version`。本课无需安装 OpenCV，也无需开发板。

用编辑器打开仓库根目录，使用它的终端。运行：

```powershell
python examples/camera_tracker/simulate.py
python -m unittest discover -s tests -v
```

模拟程序输出目标的画面位置、构图误差、云台脉宽与模式，并把记录保存到 `results/simulation.csv`。它用一个简化的虚拟相机模型，不是真实舵机的性能证明。

## 看懂第一个算例

画面宽 640 像素，主体中心在 x=480，构图目标在 x=320：横向误差是 `(480-320)/640=0.25`，即偏离画面宽度的四分之一。若本周期只按小步长向正确方向转动，下一帧的误差应变小。这就是负反馈。方向反了，误差会越转越大。

## 实操 L00

1. 运行模拟，保存原始 CSV。
2. 执行 `python examples/camera_tracker/simulate.py --target-x 0.333333`，将构图目标改为左侧三分线。
3. 比较最终主体位置与原来的差异。
4. 打开 `examples/camera_tracker/core.py`，查找 `deadband`、`max_rate`、`timeout`，只阅读含义，暂不随意放大。

**通过条件：** 能找到输出文件；能解释 x 从 0 到 1 表示从画面左到右；知道模拟中的 LOST 表示暂时没有有效目标，STOP 表示需要显式重新启动。

## 练习

E00：画面宽 800，主体中心 600，目标点在画面宽度的 1/3，求归一化误差。再解释“画面偏右”和“云台往哪转”为什么不是一回事。
